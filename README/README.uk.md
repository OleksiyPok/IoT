## Структура проєкту

Проєкт призначений для збору, перевірки, обробки та передачі даних з датчиків.

Основні модулі:

```text
src/
├── actions/       — дії та керування
├── buttons/       — кнопки
├── clock/         — час та NTP
├── config.h       — налаштування часу, порогів і GPIO
├── dht_sensor/    — температура та вологість
├── indication/    — LED-індикація
├── ldr_sensor/    — освітленість
├── memory/        — контроль пам'яті
├── monitor/       — Serial Monitor
├── mqtt/          — MQTT
├── telemetry/     — структура та статус телеметрії
└── wifi/          — Wi-Fi
```

## Структура вимірювання

Для кожного вимірювання використовується однакова послідовність:

```text
Вимірювання
    ↓
Перевірка коректності
    ↓
Робочі / аварійні пороги
    ↓
Статус
    ↓
LED / MQTT / Monitor
```

### DHT22

Вимірюються:

- температура, °C;
- відносна вологість, %.

**Температура**

- допустимий діапазон: `-35 ... 75 °C`;
- мінімальний аварійний поріг: `20 °C`;
- максимальний аварійний поріг: `26 °C`.

**Вологість**

- допустимий діапазон: `10 ... 90 %`;
- мінімальний аварійний поріг: `20 %`;
- максимальний аварійний поріг: `80 %`.

Границі допустимого діапазону є валідними. Аварійний стан виникає при виході значення **за** встановлений поріг.

Налаштовувані під час компіляції параметри:

```cpp
DHT_TEMPERATURE_ALARM_MIN_CONFIG
DHT_TEMPERATURE_ALARM_MAX_CONFIG
DHT_HUMIDITY_ALARM_MIN_CONFIG
DHT_HUMIDITY_ALARM_MAX_CONFIG
```

### LDR

Вимірюються:

- сире значення ADC;
- освітленість, lux.

**ADC**

Робочий діапазон:

```text
51 ... 4044
```

Значення `50` і `4045` вважаються некоректними.

**Освітленість**

- допустимий діапазон: `1 ... 70000 lux`;
- мінімальний аварійний поріг: `10 lux`;
- поріг низької освітленості: `600 lux`;
- максимальний аварійний поріг: `10000 lux`.

Налаштовувані під час компіляції параметри:

```cpp
LDR_LUX_ALARM_MIN_CONFIG
LDR_LUX_THRESHOLD_LIGHT_LOW_CONFIG
LDR_LUX_ALARM_MAX_CONFIG
```

Параметри перетворення ADC → lux також задаються під час компіляції:

```cpp
LDR_GAMMA
RL10
LDR_R_DIV_OHM
LDR_VCC_V
```

Вони відповідають характеристикам LDR та схеми підключення, а не аварійним порогам.

## Статуси

Статуси зберігають результат перевірки вимірювань та стан системи.

Використовуються окремі біти для:

- помилки пристрою;
- некоректного значення;
- застарілого значення;
- мінімального аварійного порогу;
- максимального аварійного порогу;
- низької освітленості;
- Wi-Fi;
- MQTT;
- Silent Mode.

Це дозволяє передавати значення вимірювань і їхній стан незалежно.

## Телеметрія

Структура телеметрії:

```cpp
struct Telemetry {
    uint8_t version;
    uint64_t deviceId;
    uint32_t timestamp;
    uint32_t uptime;
    uint8_t sequence;

    DHTData dht;
    LDRData ldr;

    uint8_t status;
};
```

Для кожного датчика передаються:

```text
виміряне значення
час оновлення
uptime оновлення
статус
```

Поточна MQTT-передача використовує окремі повідомлення для даних датчиків і статусів.

## Періодичність

Основні інтервали задаються у `config.h`:

```cpp
BUTTONS_READ_INTERVAL_MS
ACTIONS_MS
INDICATION_CHANGE_INTERVAL_MS
WIFI_CHECK_INTERVAL_MS
SENSOR_DHT_READ_INTERVAL_MS
SENSOR_LDR_READ_INTERVAL_MS
DATA_SEND_INTERVAL_MS
MQTT_PUBLISH_INTERVAL_MS
MEMORY_CHECK_INTERVAL_MS
```

Інтервал оновлення телеметрії визначається автоматично за найменшим інтервалом опитування датчиків:

```cpp
TELEMETRY_UPDATE_INTERVAL_MS
```

## GPIO

Піни також задаються під час компіляції у `config.h`.

Для іменування використовується суфікс `PIN`:

```cpp
LDR_ADC_PIN
DHT_PIN
BUTTON_0_PIN
BUTTON_1_PIN
BUTTON_2_PIN
...
```

## Конфігурація

Основні параметри, які можуть змінюватися без зміни логіки модулів, зосереджені у:

```text
src/config.h
```

Це дозволяє змінювати пороги вимірювань, інтервали роботи та GPIO на етапі компіляції.
