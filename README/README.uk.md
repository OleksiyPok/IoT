## Опис проєкту

Проєкт є прошивкою для ESP32, організованою у незалежні функціональні модулі.

Основні модулі відповідають за:

- отримання та перевірку даних із сенсорів;
- обробку телеметрії та статусів;
- обробку кнопок і постановку команд у чергу;
- LED-індикацію;
- WiFi та MQTT-зв'язок;
- серіалізацію та десеріалізацію JSON;
- виведення даних у Serial Monitor.

Основний процес вимірювання:

```text
DHT22 ──> Temperature ──┐
          Humidity ─────┤
                        ├──> Validation ──> Sensor Status ──┐
LDR ──> ADC ──> Lux ────┘                                   │
                                                            ├──> System State
                                                            ├──> LED indication
                                                            ├──> MQTT
                                                            └──> Serial Monitor
```

Кожне значення сенсора проходить перевірку за допустимими межами та робочими/аварійними порогами. Дані сенсора також містять власні мітки часу оновлення та uptime.

## Структура даних

Внутрішня телеметрія містить версію протоколу, інформацію про пристрій, дані часу, вимірювання сенсорів, регістри статусів сенсорів і системний статус.

```cpp
struct DHTData {
  float temperature; // °C
  float humidity;    // %
  uint32_t updated;
  uint32_t uptime;
  uint16_t status;
};

struct LDRData {
  uint16_t raw; // ADC data (0–4095)
  float lux;    // lux
  uint32_t updated;
  uint32_t uptime;
  uint16_t status;
};

struct Telemetry {
  uint8_t version; // protocol version
  uint64_t deviceId;
  uint32_t timestamp;
  uint32_t uptime;
  uint8_t sequence;
  DHTData dht;
  LDRData ldr;
  uint16_t status; // system status register
};
```

Поточна версія протоколу телеметрії — `1`.

Номер послідовності є 8-бітним лічильником і автоматично переходить до `0` після `255`.

## Структура вимірювання

### Температура

| Параметр | Значення |
|---|---:|
| Мінімальне допустиме значення | −35 °C (`DHT_TEMPERATURE_VALID_MIN`) |
| Мінімальний аварійний поріг | 20 °C (`DHT_TEMPERATURE_ALARM_MIN_CONFIG`) |
| Максимальний аварійний поріг | 26 °C (`DHT_TEMPERATURE_ALARM_MAX_CONFIG`) |
| Максимальне допустиме значення | +75 °C (`DHT_TEMPERATURE_VALID_MAX`) |

```text
< -35 °C        недійсне значення
-35 ... <20 °C  допустиме, низька температура
20 ... 26 °C    нормальний діапазон
>26 ... 75 °C   допустиме, висока температура
>75 °C          недійсне значення
```

Аварійні пороги можна змінити під час компіляції за допомогою:

- `DHT_TEMPERATURE_ALARM_MIN_CONFIG`
- `DHT_TEMPERATURE_ALARM_MAX_CONFIG`

Межі перевірки є константами, що задаються під час компіляції:

- `DHT_TEMPERATURE_VALID_MIN`
- `DHT_TEMPERATURE_VALID_MAX`

Помилка читання DHT22 повідомляється як помилка пристрою. Значення за межами допустимого діапазону додатково позначаються як недійсні дані.

### Вологість

| Параметр | Значення |
|---|---:|
| Мінімальне допустиме значення | 10 % (`DHT_HUMIDITY_VALID_MIN`) |
| Мінімальний аварійний поріг | 20 % (`DHT_HUMIDITY_ALARM_MIN_CONFIG`) |
| Максимальний аварійний поріг | 80 % (`DHT_HUMIDITY_ALARM_MAX_CONFIG`) |
| Максимальне допустиме значення | 90 % (`DHT_HUMIDITY_VALID_MAX`) |

```text
<10 %          недійсне значення
10 ... <20 %   допустиме, низька вологість
20 ... 80 %    нормальний діапазон
>80 ... 90 %   допустиме, висока вологість
>90 %          недійсне значення
```

Аварійні пороги можна змінити під час компіляції за допомогою:

- `DHT_HUMIDITY_ALARM_MIN_CONFIG`
- `DHT_HUMIDITY_ALARM_MAX_CONFIG`

Межі перевірки є константами, що задаються під час компіляції:

- `DHT_HUMIDITY_VALID_MIN`
- `DHT_HUMIDITY_VALID_MAX`

### Освітленість

LDR формує значення ADC, яке перетворюється на люкси за допомогою налаштованої моделі LDR.

#### Перевірка ADC

| Параметр | Значення |
|---|---:|
| Мінімальне допустиме значення | 50 (`LDR_ADC_VALID_MIN`) |
| Максимальне допустиме значення | 4045 (`LDR_ADC_VALID_MAX`) |

Поточна реалізація вважає самі граничні значення такими, що знаходяться за межами робочого діапазону ADC. Це дозволяє виявляти значення ADC поблизу шин живлення як помилки пристрою.

#### Люкси

| Параметр | Значення |
|---|---:|
| Мінімальне допустиме значення | 1 lux (`LDR_LUX_VALID_MIN`) |
| Мінімальний аварійний поріг | 10 lux (`LDR_LUX_ALARM_MIN_CONFIG`) |
| Поріг низької освітленості | 600 lux (`LDR_LUX_THRESHOLD_LIGHT_LOW_CONFIG`) |
| Максимальний аварійний поріг | 10,000 lux (`LDR_LUX_ALARM_MAX_CONFIG`) |
| Максимальне допустиме значення | 70,000 lux (`LDR_LUX_VALID_MAX`) |

```text
<1 lux               недійсне значення
1 ... <10 lux        допустиме, аварійно низька освітленість
10 ... <600 lux      допустиме, низька освітленість
600 ... 10,000 lux   нормальний робочий діапазон
>10,000 ... 70,000   допустиме, аварійно висока освітленість
>70,000 lux          недійсне значення
```

Наступні пороги освітленості можна змінити під час компіляції:

- `LDR_LUX_ALARM_MIN_CONFIG`
- `LDR_LUX_THRESHOLD_LIGHT_LOW_CONFIG`
- `LDR_LUX_ALARM_MAX_CONFIG`

Межі перевірки ADC та люксів також є константами, що задаються під час компіляції:

- `LDR_ADC_VALID_MIN`
- `LDR_ADC_VALID_MAX`
- `LDR_LUX_VALID_MIN`
- `LDR_LUX_VALID_MAX`

Модель перетворення LDR використовує додаткові константи, що задаються під час компіляції:

- `LDR_GAMMA`
- `RL10`
- `LDR_R_DIV_OHM`
- `LDR_VCC_V`

## Регістри статусів

Стан сенсорів і системи представлений бітовими прапорами, що зберігаються у 16-бітних регістрах статусів.

Регістри статусів DHT і LDR можуть містити інформацію про помилки пристрою, недійсні дані, прапори застарілих даних та аварійні умови сенсорів.

Системний регістр статусу може містити інформацію про команди, тихий режим, помилки сенсорів та помилки зв'язку WiFi/MQTT.

Такий підхід дозволяє одночасно представляти декілька незалежних станів в одному значенні статусу.

Системний статус телеметрії містить такі умови:

- `STATUS_DEVICE_SILENT_MODE`
- `STATUS_LDR_ERR`
- `STATUS_DHT_ERR`
- `STATUS_MQTT_ERR`
- `STATUS_WIFI_ERR`

## Кнопки та індикація

Визначено чотири входи для кнопок. Поточні функції керування:

- формування ручної команди;
- тихий режим;
- тестування відключення/відновлення WiFi.

Події кнопок зберігаються у 16-бітному регістрі стану кнопок. Натискання кнопки ручної команди створює команду `manual_read` і додає її до черги разом із номером послідовності. Черга може містити до чотирьох команд, що очікують на публікацію.

Світлодіоди відображають:

- ручну/командну активність;
- автоматичний режим освітлення та аварійні стани освітленості;
- аварійні стани температури;
- аварійні стани вологості;
- тихий режим.

## Зв'язок

Пристрій підключається через WiFi та передає дані через MQTT.

MQTT-інтерфейс використовує такі топіки:

- `iot-course/OleksiiPok/sensors`
- `iot-course/OleksiiPok/status`
- `iot-course/OleksiiPok/commands`

Дані сенсорів і статус публікуються окремими JSON-повідомленнями. Командні повідомлення містять назву команди та номер послідовності.

У тихому режимі передача повідомлення з даними сенсорів призупиняється, але повідомлення зі статусом продовжує публікуватися. Таким чином, стан тихого режиму залишається доступним без передачі повідомлення з вимірюваннями.

Відновлення MQTT-з'єднання виконується автоматично. Один цикл з'єднання містить до п'яти спроб з інтервалом п'ять секунд; після цього наступний цикл починається через п'ять хвилин.

Проєкт також містить підтримку HTTP POST для серіалізації повної телеметрії. HTTP-модуль доступний, але в поточній конфігурації прошивки його відправлення не виконується в основному циклі.

## Серіалізація

Проєкт містить окремі серіалізатори для:

- повної телеметрії;
- даних сенсорів;
- статусу;
- команд.

Основний серіалізатор телеметрії використовує `snprintf`. Альтернативний серіалізатор на ArduinoJson можна вибрати під час компіляції за допомогою:

`TELEMETRY_SERIALIZER_ARDUINO_JSON`

Також доступний десеріалізатор телеметрії для перевірки та відновлення структури `Telemetry` з JSON. Він перевіряє версію протоколу та типи обов'язкових полів перед прийняттям даних.

## Конфігурація

Пороги сенсорів, межі перевірки сенсорів, параметри перетворення, інтервали роботи та апаратні піни можна налаштовувати під час компіляції.

Основна конфігурація знаходиться у `src/config.h`. Налаштування MQTT знаходяться у `src/mqtt/mqtt_config.h`.

Поточні значення призначені переважно для тестування та можуть бути змінені для реального використання.
