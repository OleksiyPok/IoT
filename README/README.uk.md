## Опис проекту

Проект — прошивка для ESP32, организованная в независимые функциональные модули.

Основные модули отвечают за:
- получение данных с датчиков;
- обработку телеметрии и состояний;
- обработку кнопок;
- светодиодную индикацию;
- WiFi и MQTT;
- вывод в Serial Monitor.

Основной поток измерений:

```text
DHT22 ──> Температура ──┐
        Влажность ──────┤
                        ├──> Проверка ──> Состояние
LDR ──> ADC ──> Lux ────┘                  │
                                           ├──> LED
                                           ├──> MQTT
                                           └──> Serial Monitor
```

Каждое измерение проходит проверку допустимости и сравнение с рабочими/аварийными порогами.

## Структура данных

Внутренняя телеметрия содержит идентификатор устройства, временные данные, измерения датчиков и регистры состояний.

```cpp
struct DHTData {
    float temperature; // °C
    float humidity;    // %
    uint8_t status;
};

struct LDRData {
    uint16_t raw; // данные ADC
    float lux;    // lux
    uint8_t status;
};

struct Telemetry {
    uint64_t deviceId;
    uint32_t timestamp;
    uint32_t uptime;
    uint32_t sequence;
    DHTData dht;
    LDRData ldr;
    uint8_t status; // регистр состояния системы
};
```

По MQTT данные передаются отдельными сообщениями с измерениями и состояниями.

## Структура измерений

### Температура

| Параметр | Значение |
|---|---:|
| Минимальное допустимое | −35 °C (`DHT_TEMPERATURE_VALID_MIN`) |
| Нижний аварийный порог | 20 °C (`DHT_TEMPERATURE_ALARM_MIN_CONFIG`) |
| Верхний аварийный порог | 26 °C (`DHT_TEMPERATURE_ALARM_MAX_CONFIG`) |
| Максимальное допустимое | +75 °C (`DHT_TEMPERATURE_VALID_MAX`) |

```text
< -35 °C        недопустимо
-35 ... <20 °C  допустимо, низкая температура
20 ... 26 °C    нормальный диапазон
>26 ... 75 °C   допустимо, высокая температура
>75 °C          недопустимо
```

При компиляции можно изменять:
- `DHT_TEMPERATURE_ALARM_MIN_CONFIG`
- `DHT_TEMPERATURE_ALARM_MAX_CONFIG`

Пределы допустимости также являются константами компиляции:
- `DHT_TEMPERATURE_VALID_MIN`
- `DHT_TEMPERATURE_VALID_MAX`

### Влажность

| Параметр | Значение |
|---|---:|
| Минимальное допустимое | 10 % (`DHT_HUMIDITY_VALID_MIN`) |
| Нижний аварийный порог | 20 % (`DHT_HUMIDITY_ALARM_MIN_CONFIG`) |
| Верхний аварийный порог | 80 % (`DHT_HUMIDITY_ALARM_MAX_CONFIG`) |
| Максимальное допустимое | 90 % (`DHT_HUMIDITY_VALID_MAX`) |

```text
<10 %          недопустимо
10 ... <20 %   допустимо, низкая влажность
20 ... 80 %    нормальный диапазон
>80 ... 90 %   допустимо, высокая влажность
>90 %          недопустимо
```

При компиляции можно изменять:
- `DHT_HUMIDITY_ALARM_MIN_CONFIG`
- `DHT_HUMIDITY_ALARM_MAX_CONFIG`

Пределы допустимости:
- `DHT_HUMIDITY_VALID_MIN`
- `DHT_HUMIDITY_VALID_MAX`

### Освещённость

LDR формирует значение ADC, которое преобразуется в lux.

#### Проверка ADC

| Параметр | Значение |
|---|---:|
| Нижняя граница | 50 (`LDR_ADC_VALID_MIN`) |
| Верхняя граница | 4045 (`LDR_ADC_VALID_MAX`) |

В текущей реализации сами граничные значения считаются выходящими за рабочий диапазон ADC.

#### Lux

| Параметр | Значение |
|---|---:|
| Минимальное допустимое | 1 lux (`LDR_LUX_VALID_MIN`) |
| Нижний аварийный порог | 10 lux (`LDR_LUX_ALARM_MIN_CONFIG`) |
| Порог низкой освещённости | 600 lux (`LDR_LUX_THRESHOLD_LIGHT_LOW_CONFIG`) |
| Верхний аварийный порог | 10 000 lux (`LDR_LUX_ALARM_MAX_CONFIG`) |
| Максимальное допустимое | 70 000 lux (`LDR_LUX_VALID_MAX`) |

```text
<1 lux             недопустимо
1 ... <10 lux      допустимо, нижняя авария
10 ... <600 lux    допустимо, низкая освещённость
600 ... 10 000 lux нормальный рабочий диапазон
>10 000 ... 70 000 допустимо, верхняя авария
>70 000 lux        недопустимо
```

При компиляции можно изменять:
- `LDR_LUX_ALARM_MIN_CONFIG`
- `LDR_LUX_THRESHOLD_LIGHT_LOW_CONFIG`
- `LDR_LUX_ALARM_MAX_CONFIG`

Пределы допустимости:
- `LDR_ADC_VALID_MIN`
- `LDR_ADC_VALID_MAX`
- `LDR_LUX_VALID_MIN`
- `LDR_LUX_VALID_MAX`

Параметры модели преобразования LDR также задаются константами компиляции: `LDR_GAMMA`, `RL10`, `LDR_R_DIV_OHM`, `LDR_VCC_V`.

## Регистры состояний

Состояния датчиков и системы представлены битовыми флагами.

Регистры DHT, LDR и системы могут содержать признаки ошибки устройства, недопустимых или устаревших данных, аварийных значений и ошибок связи.

Несколько независимых состояний могут быть установлены одновременно.

## Кнопки и индикация

Три кнопки управляют:
- ручным режимом освещения;
- тихим режимом;
- отключением WiFi для проверки восстановления соединения.

Светодиоды показывают режимы освещения, аварии освещённости, температуры и влажности, а также тихий режим.

## Связь

Устройство подключается к WiFi и передаёт телеметрию через MQTT.

Также поддерживается вывод данных в Serial Monitor.

При отключении WiFi автоматически запускается процедура восстановления соединения.

## Конфигурация

Пороговые значения датчиков, пределы проверки, параметры преобразования LDR и интервалы работы задаются на этапе компиляции.

Текущие значения предназначены прежде всего для тестирования и могут быть изменены для реальной эксплуатации.
