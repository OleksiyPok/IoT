## Опис проєкту

Проєкт є прошивкою ESP32 для моніторингу параметрів навколишнього середовища, обробки станів пристрою та передавання телеметрії.

Прошивка організована в окремі модулі для:

* моніторингу температури та вологості через DHT22;
* вимірювання освітленості LDR та розрахунку lux;
* обробки телеметрії та статусів;
* кнопок і дій пристрою;
* LED-індикації;
* керування Wi-Fi та синхронізації часу NTP;
* MQTT-комунікації;
* діагностики через Serial Monitor.

## Структура проєкту

Основні модулі:

* `dht_sensor` — температура, вологість, перевірка даних, аварійні пороги та статус сенсора;
* `ldr_sensor` — ADC, розрахунок lux, перевірка даних, аварійні пороги та статус сенсора;
* `telemetry` — загальні дані пристрою, час, uptime, sequence та watchdog STALE;
* `system` — агрегований стан системи;
* `buttons` — фізичні кнопки;
* `actions` — команди пристрою та обробка стану LED;
* `indication` — патерни LED-індикації;
* `wifi` — керування Wi-Fi-з'єднанням;
* `time` — NTP-синхронізація та часова зона;
* `mqtt` — MQTT-з'єднання, публікація та сервіси;
* `serialization` — JSON для телеметрії, статусів і команд;
* `monitor` — діагностичний вивід.

## Дані телеметрії

Внутрішня структура телеметрії містить:

* версію протоколу;
* ID пристрою;
* timestamp;
* uptime;
* номер sequence;
* дані DHT22;
* дані LDR;
* стан кнопок;
* стан системи;
* стан LED.

Дані DHT22 містять:

* температуру;
* вологість;
* час останнього успішного оновлення;
* uptime оновлення;
* статус.

Дані LDR містять:

* значення ADC;
* розраховане значення lux;
* час останнього успішного оновлення;
* uptime оновлення;
* статус.

## STATE, STALE та агрегація статусів

### STATE

`systemState` — бітове поле, що відображає поточні стани системи.

Воно містить керовані стани:

* silent mode;
* активність команди;

а також системні помилки:

* DHT;
* LDR;
* Wi-Fi;
* синхронізації часу;
* MQTT.

Прапорці помилок спочатку вважаються активними та очищаються лише після підтвердження нормального стану відповідної підсистеми.

### STALE

`STALE` — прапорець актуальності даних сенсора.

Watchdog періодично встановлює `STALE` для DHT і LDR. Успішне читання сенсора очищає відповідний прапорець `STALE`. Якщо читання неуспішне, `STALE` залишається активним.

Таким чином, `STALE` означає, що нове успішне оновлення даних ще не підтверджене.

### Агрегація статусів

Статуси DHT і LDR зберігаються окремо.

`systemState` агрегує основні помилки сенсорів і комунікацій у системні прапорці. LED-індикація та інші дії використовують ці стани без дублювання вихідних статусів сенсорів.

## MQTT-комунікація

Пристрій передає дані через MQTT відповідно до налаштованого MQTT-сервісу.

MQTT-інтерфейс використовує три типи повідомлень:

* `telemetry` — дані сенсорів разом із загальними полями телеметрії та станом системи;
* `status` — статуси DHT, LDR і системи;
* `commands` — команди пристрою.

Повідомлення телеметрії та статусів містять:

* версію протоколу;
* ID пристрою;
* timestamp;
* uptime;
* sequence;
* статус DHT;
* статус LDR;
* system state.

Телеметрія додатково містить температуру та вологість DHT, а також ADC і lux для LDR.

Команди передаються у форматі JSON.

## Конфігурація

Основні часові інтервали визначаються у `src/app_config.h`.

Піни апаратної частини визначаються у `src/hardware_config.h`.

Межі та аварійні пороги сенсорів визначаються у:

* `src/dht_sensor/dht_config.h`;
* `src/ldr_sensor/ldr_config.h`.

MQTT-сервіс і топіки визначаються у `src/mqtt/mqtt_config.h`.

Налаштування часової зони та NTP визначаються у `src/time/time_config.h`.

## Debug Monitor

Якщо увімкнено `DEBUG_MODE`, Serial Monitor виводить інформацію про дані сенсорів, стан системи, події підключення та MQTT payload.
